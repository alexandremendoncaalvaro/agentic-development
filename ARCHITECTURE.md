# Architecture

System-level patterns and boundaries. Pair with ADRs in [`doc/adr/`](doc/adr/) for individual decisions.

## Overview

Single-binary Node CLI that installs operational skills (`AGENTS.md` / `ARCHITECTURE.md` / ADR / spec / task / `DESIGN.md` / skill / subagent / drift / fresh-context review / four-source research) into the user's global agent surface by default, refreshing it through a state-aware three-way diff. A project-local materialization is an explicit sharing or pinning exception. Phase 1 (this CLI) does filesystem work only — detect, copy, append, three-way-merge. Phase 2 (the installed skills) runs inside Claude Code or Codex CLI and produces the actual artifacts via the agent's native conversational UI ([ADR-0002](doc/adr/0002-two-phase-architecture.md)). Runtime deps: `commander` (arg parsing), `@clack/prompts` (TUI). Distributed on npm as `@alexandrealvaro/agentic`.

## Layers & Boundaries

Three execution layers under `src/`, plus kit content read at runtime:

* `bin/agentic.js` — shebang shim. Imports `run` from `src/index.js`, forwards `process.argv`. Catches errors, prints `agentic: <message>`, exits 1.
* `src/index.js` — Commander setup. Defines commands and options, dispatches to `src/commands/<name>.js`. No business logic.
* `src/commands/<name>.js` — command actions. `init.js` and `update.js` resolve user scope by default, install every bundled skill for each selected agent, write state, and maintain the machine-global Constitution; their explicit project scope retains root-document safeguards and the `.git/info/exclude` offer. `update --scope project --migrate-legacy` retires a former local materialization. `uninstall.js` removes only exact state-recorded files, preserves divergences unless `--force`, and retains state for preserved files. Command-layer logic shared by init/update (the `.git/info/exclude` offer, `offerKitExclude` / `kitExcludeCandidates`) lives in `src/commands/kit-exclude.js`, so the two commands depend on shared code rather than importing behaviour from each other. It sits in `src/commands/` rather than `src/lib/` because it calls `@clack/prompts`, which the pure `src/lib/` layer excludes.
* `src/lib/<name>.js` — pure helpers. `detect.js` reads filesystem signals; `install.js` copies skill source to target with state-aware three-way diff and manifest-based subagent routing, removes only unchanged orphan files, and applies declared retirements as all-or-nothing migrations; `legacy-project-migration.js` removes only proven project-local artifacts during the explicit migration; `skill-migrations.js` records the old paths and fingerprints a retirement may remove; `state.js` reads / writes per-agent state files; `rootdoc.js` manages the bounded skills section in a project root doc; `global-rules.js` preserves host-global instructions while importing the global Constitution; `git.js` reads git state — whether a path is tracked, and writes per-clone `.git/info/exclude` entries — for the installer's shared-write guard ([ADR-0051](doc/adr/0051-installer-shared-write-target-detection.md)). Every `git.js` probe is fail-open: an unresolvable repository yields `unknown` and never blocks an install, the deliberate opposite of `src/leak-guard.js`, which is fail-closed on the same surface.

Kit content lives under `src/skills/<agent>/<skill>/` and is read at runtime by `src/lib/install.js` only:

* `src/skills/claude-code/<skill>/SKILL.md` — Markdown body, Anthropic Skills frontmatter, optional `manifest.json` declaring sibling-tree subagent files, optional `agents/<subagent>.md` files routed to `.claude/agents/`, optional `scripts/` skill scripts installed with the skill (byte-identical across hosts, per task-0031).
* `src/skills/codex/<skill>/SKILL.md` plus `agents/openai.yaml` — XML body + minimal frontmatter (cc-sdd convention); same optional `scripts/` skill scripts as the claude-code tree (byte-identical twins, parity-tested).
* `scripts/` — repo-only release and git-hook tooling ([ADR-0048](doc/adr/0048-kit-release-discipline-gates.md)): `release.sh` (with `release-apply.js` + the pure `release-lib.js`) and the lefthook gate scripts (`changelog-gate.js`, `commit-subject-check.js`, `push-branch-guard.js`). Wired by `lefthook.yml`; excluded from `package.json#files`, so none of it ships to npm.
* `doc/adr/`, `doc/tasks/`, `AGENTS.md`, `ARCHITECTURE.md`, `CHANGELOG.md` — kit documentation. Not loaded at runtime.
* `WORKFLOW.md`, `WORKFLOW-FLOWS.md` — the kit-shipped Layer 1 Constitution. `installKitDocs` keeps the pair once at `~/.agentic/kit/`, and the host-global instruction files import it there ([ADR-0069](doc/adr/0069-global-first-kit-installation.md)). A diverged global copy is reported and skipped, never overwritten without `--force`.

Boundary rule: only `src/lib/install.js` resolves `KIT_ROOT`-rooted paths (`import.meta.url` → `..`). Layers above never read `src/skills/` directly. AGENTS.md gotcha §89 documents the fragility (moving `install.js` breaks the path).

## Patterns

* **Mode detection:** filesystem-driven. `detectMode(dir)` returns `audit | greenfield | brownfield` from presence of `AGENTS.md` and count of meaningful entries (filtered by `TRIVIAL_ENTRIES` + dotfile prefix). `detectAgents(dir)` returns `['claude-code'?, 'codex'?]` from `.claude/` and `.agents/` for the interactive UI and legacy-update fallback.
* **Skill installation (state-aware three-way diff):** `installSkills({ cwd, agents, skills, confirmReplace, previousStates, kitVersion, dryRun, force })` walks each skill source tree and decides per file by comparing the kit's current source SHA, the SHA recorded at the previous install (from state), and the target file's current SHA. Outcomes: `created` / `unchanged` / `kit-changed-update` (silent) / `user-edited-keep` (silent) / `conflict-prompt` (default skip) / `conflict-force` (when `--force`) / `legacy-divergent` (no prior state — falls back to byte-compare). Returns `nextStates` so callers persist the post-install picture. Optional `manifest.json` at the skill root declares files that route to `<layout.agentsDir>/<basename>` instead of the default `<layout.skillsDir>/<skill>/<rel>` path; manifest itself is never installed; declared paths must exist in source or the installer throws. Both layouts declare an `agentsDir` — `.claude/agents` for Claude Code, `.codex/agents` for Codex — so manifest-listed subagents install on both hosts. `removeRetiredSkills` handles named replacements declared in `skill-migrations.js`: it removes every managed legacy file only when all still match saved or known source fingerprints, preserving the whole legacy skill if one diverged. `removeOrphanSkills` covers skills that leave the bundled source set and applies the same unchanged-file rule (default keep).
* **Per-host installation:** `init.js` and `update.js` call `installSkills` once per selected agent with every directory under that host's `src/skills/<agent>/` source tree. User scope targets the home directory by default; project scope is explicit. A bare non-interactive `init` targets both hosts; `--agent claude-code|codex|both` is authoritative. The interactive UI selects hosts, then confirms the complete set.
* **Root doc handling:** only project scope calls `updateRootDoc({ cwd, skills, confirmAppend, confirmReplace })`, which looks for `AGENTS.md` (preferred) or `CLAUDE.md` (fallback). Absent → no-op. Section already present and fresh → unchanged. Section present and stale → rewritten in place (`confirmReplace`); bytes outside the markers preserved. Section absent + `confirmAppend(path) === true` → appended at EOF. Markers: `<!-- agentic-managed-skills:start -->` / `:end -->`. The explicit legacy migration removes that bounded section rather than recreating it.
* **Shared-write guard ([ADR-0051](doc/adr/0051-installer-shared-write-target-detection.md)):** a project root doc is often team-shared, so a non-interactive project-scope run refuses to write its managed section when `trackedState` reports `tracked` — it skips, states why on stderr, and continues; `--force-root-doc` overrides, and is scoped to the tracked case only (on an untracked doc the pre-existing `--force` alone governs overwriting a hand-edited section). The project installer offers (interactive) to add its still-untracked **agent-surface** files (`.claude/`, `.agents/`, `.codex/` — `kitExcludeCandidates`) to `.git/info/exclude` by filename — never by directory, since a mixed-ownership `.claude/agents/` can hold a team-tracked file beside the kit's reviewers. User scope makes neither project write.
* **Interactive vs non-interactive:** `init` runs the TUI when `process.stdout.isTTY && !opts.yes && !opts.agent`. `--agent claude-code|codex|both` and `--yes` both bypass the TUI. Interactive cancellations are explicit (`p.isCancel(value)` → `p.cancel(...)` → return).
* **Output dispatch:** TUI uses `@clack/prompts` panels (`p.intro`, `p.note`, `p.outro`); non-interactive writes per-file action lines to `stderr` so `stdout` stays parseable.
* **Input validation:** Commander parses args; `init` enforces an enum guard on `--agent` via `AGENT_FLAG_VALUES`. No schema library — the option surface is a single string enum and a boolean.
* **Error handling:** thrown errors bubble to `bin/agentic.js`, which prints `agentic: <message>` and exits 1. No try/catch inside command logic, except `loadManifest` which wraps `JSON.parse` to give a useful message on malformed manifest.
* **Workflow-operational vs spec-driven skills:** ([ADR-0007](doc/adr/0007-workflow-operational-skills.md)) skills fall in two categories — **workflow-operational** skills execute a process from `WORKFLOW.md` or the kit's commit/PR/merge conventions (for example `ad-ground`, `ad-review`, `ad-diagnose`), and **spec-driven** skills produce a documentation artifact (for example `ad-spec`, `ad-adr`, `ad-research`). The grouped skill reference in [`doc/guides/skills.md`](doc/guides/skills.md) is the canonical catalog; the category is informational and the install path is the same. `ad-review` ships with a bundled subagent at `.claude/agents/fresh-context-reviewer.md` via the manifest mechanism.
* **Machine-local personal voice:** ([ADR-0068](doc/adr/0068-layer-personal-voice-evidence.md)) `ad-voice` reads a confirmed profile while `ad-voice-tune` alone may change it behind explicit source-read and per-delta write approvals. Both use the same zero-dependency profile script and versioned Markdown contract. Resolution is explicit path, `$AGENTIC_VOICE_DIR/profile.md`, then `~/.agentic/voice/profile.md`; profile content remains outside the project and kit state. Identity, community accommodation, and situational context stay separately attributed.
* **Six-layer artifact stack** ([WORKFLOW.md §1](WORKFLOW.md)): Constitution (`AGENTS.md` + `WORKFLOW.md` + `GUIDELINES.md`) → Domain (`CONTEXT.md` — ubiquitous language per Evans 2003, lazy-created) → Product (`doc/product/PRD.md`) → Spec (`doc/specs/NNNN-<slug>.md`) → Plan / Decisions (`ARCHITECTURE.md` + `doc/adr/` + `doc/tasks/`) → Code. Each artifact has its own scaffolding skill; tasks carry an optional `Spec ref` field linking back to the spec they implement.
* **Architectural vocabulary:** ([ADR-0020](doc/adr/0020-deep-modules-vocabulary.md), [WORKFLOW.md §8](WORKFLOW.md)) Module / Interface / Implementation / Depth / Seam / Adapter / Leverage / Locality drawn from Ousterhout 2018 + Feathers 2004. Used verbatim in new architectural prose; depth-as-line-ratio framing rejected.

## Naming Conventions

* ES modules (`"type": "module"` in `package.json`). Built-in imports use the `node:` prefix (`node:fs`, `node:path`, `node:url`).
* Skill scripts use the `.mjs` extension — they execute inside consumer projects where no `"type": "module"` `package.json` is in scope, so ESM must be declared by extension. The kit's own `src/*.js` stays `.js` under the root `package.json`.
* Files: kebab-case (`init.js`, `detect.js`, `install.js`, `rootdoc.js`).
* Exports: camelCase functions (`detectMode`, `detectAgents`, `installSkills`, `updateRootDoc`, `initCommand`).
* Skill names: `ad-<verb-or-noun>` (`ad-bootstrap`, `ad-architecture`, `ad-review`). Historical skills under closed ADRs / tasks may reference the pre-rename `agentic-<verb-or-noun>` prefix.
* Agent values: lowercase strings (`'claude-code' | 'codex' | 'both'`).

## Observability

* Logs: `process.stderr.write(...)` for per-file action lines in non-interactive flows; `@clack/prompts` panels interactively. No structured logging.
* Metrics: N/A — short-lived CLI, no telemetry.
* Traces: N/A.

## Deployment Topology

Published on npm as `@alexandrealvaro/agentic` under `latest`. Consumers run `npx @alexandrealvaro/agentic init` to scaffold, `npx @alexandrealvaro/agentic update` to absorb upstream kit changes, or `npx @alexandrealvaro/agentic uninstall` to remove state-recorded files safely. No server, no daemon, no scheduled jobs. `engines.node = ">=20.12.0"`. Package contents declared by `package.json#files`: `bin/`, `src/`, `WORKFLOW.md`, `WORKFLOW-FLOWS.md`, `README.md`, `LICENSE`. `prepublishOnly` runs `npm test` (CLI `--help` smoke for `init` / `update` / `uninstall` + `node scripts/run-tests.mjs`, which enumerates `test/*.test.js` itself rather than leaving the glob to the shell).

Test layout: `test/lib.test.js` (unit — `detectMode`, `detectAgents`, `installSkills`, `updateRootDoc`), `test/init.test.js` (integration — spawns the CLI in `mktemp` directories), `test/state.test.js` (state file load / save / schema-version refusal / deterministic ordering), `test/update.test.js` (state-aware three-way diff matrix + `agentic update` end-to-end including legacy-state migration), `test/uninstall.test.js` (integration — safe state-recorded removal, preserved edits, force, and dry-run), `test/followups.test.js` (unit + integration — orphan-skill removal and update follow-up actions), `test/skills.test.js` (static — parses every `SKILL.md` frontmatter, every Codex `agents/openai.yaml`, every manifest-listed subagent file; also byte-parity of skill-script twins and the reviewer-brief contract guards), `test/release.test.js` + `test/commit-gates.test.js` (unit — `release-lib` bump/rotate logic and the lefthook gates' pure policy cores), `test/release-e2e.test.js` (integration — runs `scripts/release.sh` inside a fixture git repo), `test/skill-scripts.test.js` (integration — executes installed skill scripts against fixture repositories; host parity itself is enforced in `test/skills.test.js`), `test/lefthook-wiring.test.js` (integration — the real `lefthook.yml` installed as real git hooks exercised by a real push, plus the env-stripping pre-push runner), `test/leak-guard.test.js` (unit + integration — denylist policy core and `src/leak-guard.js` end-to-end), `test/rootdoc-crlf.test.js` (regression — CRLF-stored managed sections), `test/windows-paths.test.js` (unit — forward-slash manifest paths and Windows path handling), `test/hook-npm-test.test.js` (unit — the pre-push runner's `resolveSpawn` platform resolution and `sanitizedEnv`, with `platform` / `env` injected so the Windows branch is covered on any host).
