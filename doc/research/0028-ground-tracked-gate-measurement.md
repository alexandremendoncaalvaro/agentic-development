# GROUND-0028: Measure the artifact-validator gate through a tracked live case

**Status:** recorded
**Decision:** Add a tracked fixture whose `.claude/settings.json` wires the gate through `${CLAUDE_PROJECT_DIR}/.claude/skills/ad-hooks/scripts/artifact-gate.mjs`; let a case declare `fixture_skills`, which the live lane installs from `src/skills/<host>/` into each trial copy before spawning the host and records by digest in the receipt's `run_parameters`; run the lane with `--setting-sources project --allowedTools Skill` in the runner; relativize written paths against the trial copy; point `AD_ARTIFACT_GATE_EVIDENCE_DIR` at a per-trial directory under the lane's work root and keep the evidence beside the capture; join evidence lines with `file_write` events by path and order in a sidecar module with its own `run.mjs` subcommand; author the `ad-ground` case family (positive, close-negative routing to `ad-research`, coexistence) with synthetic receipts for the corpus gate.
**Decision ref:** doc/tasks/0084-measure-the-gate-through-the-live-lane.md (implements doc/specs/0008-surface-validator-failures-during-the-turn.md Scenario 7 and doc/adr/0083-bound-the-runtime-layer-to-feedback-gates.md decision 7 through doc/specs/0007-evaluate-skill-trajectories.md R3 and R7)
**Confidence:** Conditional

## Decision and confidence

The happy path is the one the host documents and the pilot already exercised: a `-p` session runs the hooks in the project's `.claude/settings.json` without a trust dialog, `${CLAUDE_PROJECT_DIR}` is the project root where the session started, and the lane spawns the host with a trial copy as its working directory, so a fixture that names the gate through that variable fires on any machine as long as the skills the command points at exist inside the copy (E1, E2). The lane already copies the fixture per trial (`planTrialRoots`, ADR-0082 decision 5); installing the case's declared skills into the copy is the same copy step with a second source, and `agentLayout` in `src/lib/install.js` already names each host's project skills directory, so the harness imports that one fact rather than restating it (C1). The pilot found the two conditions that make the copy insufficient on its own: personal skills outrank project skills of the same name, and the permission mode denies a read outside the working directory, so the operator's user-level `ad-ground` would shadow the fixture's copy and stay unreadable. `--setting-sources project` removes the user source; measured on the installed binary, the session then lists the fixture's project skill and the built-ins only, with no plugin and no user hook (E3). `--allowedTools Skill` lets the `Skill` tool run without a prompt, which the pilot's denied `Skill` call and the public skill-activation harnesses both point at (E4).

Two defects sit between the lane and a receipt that grades. The adapter relativizes written paths against the tracked fixture root while the writes happen in the trial copy, so a live `file_write` keeps an absolute temporary path and the effects grader refuses a permitted write; reproduced on the pilot receipt's path shape with the real grader (E5). And the stream carries no `PostToolUse` record on this host version (Task 0084 pilot), so the join anchors on the evidence file: the lane sets `AD_ARTIFACT_GATE_EVIDENCE_DIR` per trial, hooks inherit the host's environment, and the sidecar pairs evidence lines with `file_write` events by path and order (E6). The corpus rules for the new representative are the ones the existing tests enforce (E7).

Axis-2 verdict: Conditional, with two named mitigations. `--allowedTools Skill` is documented and used publicly but has not run in this lane; the first tracked trial exercises it, and if the `Skill` call is still denied the route grader's false negative (Task 0082) is recorded beside the result rather than hidden. The comparison itself runs one trial per arm, which is an anecdote with frozen inputs, not a distribution; the record states that and no gain claim is published from it. Every piece is reversible: a case field, a lane option, a sidecar module, one fixture.

## Evidence

### E1 — A `-p` session runs the hooks in a project's `.claude/settings.json` without a trust dialog, and `${CLAUDE_PROJECT_DIR}` is the project root where the session started

**Strength:** High
**Provenance:** A1, A2, A3, C2

A1: "Without `--bare`, a `-p` session runs the hooks in a project's `.claude/settings.json` and connects the servers in its `.mcp.json`, even in a folder you've never trusted. A `-p` session shows no workspace trust dialog and no per-server approval prompt." A2, the table "What runs before you trust a folder", row "Hooks in settings files": under "`claude -p` or the SDK, folder never trusted" the cell reads "Used". A3: "`${CLAUDE_PROJECT_DIR}`: the project root where the session started", with a `PostToolUse` example command `${CLAUDE_PROJECT_DIR}/.claude/hooks/check-style.sh`. C2: the pilot fixture shipped a `.claude/settings.json` `PostToolUse` entry and the gate fired three times in a `-p` session whose `cwd` was a fresh temporary copy, which is the measurement behind the documented rule. High: primary documentation on two pages, confirmed by a capture on the same host version.

### E2 — The lane can install the skills a case declares into each trial copy and freeze their identity

**Strength:** High
**Provenance:** A4, C1, C3, D1

A4: skills are discovered from `.claude/skills/<skill-name>/SKILL.md` in the project, and in `-p` mode "Skills load from `.claude/skills/` per normal precedence rules". C1: `planTrialRoots` already copies the fixture per trial with `cpSync`, and `agentLayout(agent).skillsDir` is `.claude/skills` for Claude Code and `.agents/skills` for Codex; `skillIdentity` digests a skill directory with `freezeArtifact`, so the same call records each installed skill's digest. C3: the receipt's `run_parameters` is free-form and validated only as a record, so `fixture_skills` digests fit there without a schema change, which Spec 0008 keeps out of scope. D1: no prior attempt to install skills into a fixture copy exists in any branch. High: every mechanism is in-repo and tested; the new step composes them.

### E3 — `--setting-sources project` removes the user's skills, hooks, and plugins from a `-p` session, so the fixture's project skill is the one the model sees

**Strength:** High
**Provenance:** A4, A5, A2, C4

A4, skill precedence: "Enterprise over personal, and personal over project. With `deploy` in both `~/.claude/skills/` and the project's `.claude/skills/`, `/deploy` runs the personal one", and "A list that excludes `user` prevents personal skills (`~/.claude/skills/`) from loading." A5: the installed binary's help reads "`--setting-sources <sources>` Comma-separated list of setting sources to load (user, project, local)." A2: "Pass `--setting-sources user` ... so Claude Code reads neither the project's settings files nor its `.mcp.json`", the mirror image of the project-only list. C4, the measurement: one Haiku turn in a temporary folder carrying a project skill and a project `PostToolUse` hook, run with `--setting-sources project`, produced an init record whose `skills` were the project skill plus seventeen built-ins, `slash_commands` without any `ad-*` entry, `plugins: []`, `agents` the five built-ins, and no `hook_started` record, against the pilot's 76 skills, 106 slash commands, 2 plugins, 38 agents, and a `SessionStart` plugin hook. The account's MCP connectors still connected (21 servers, 139 tools); they are account state, not a settings source, and the receipt's `context_policy` records the session as host-configured for that reason. High: documented and measured on the operator's binary.

### E4 — `--allowedTools Skill` lets the model invoke any skill without a permission prompt, so a routed trial carries a native `skill_invoked` event

**Strength:** Medium
**Provenance:** A4, A6, B1, B2, C5

A4: the permission rule `Skill` with no argument matches every skill ("Deny all skills: `Skill`" in the deny list, the same rule shape in `permissions.allow`). A6: "`--allowedTools` Tools that execute without prompting for permission. See permission rule syntax", and in `-p` guidance: "Apart from the read-only command set, other shell commands and network requests still need an `--allowedTools` entry or a `permissions.allow` rule" under `acceptEdits`. B1 runs its activation evals with `claude -p "$QUERY" --output-format stream-json --verbose --max-turns 1 --allowedTools Skill --permission-mode bypassPermissions` and detects activation from `tool_use` blocks named `Skill`; B2's trigger evals read `Skill` invocations from session streams the same way. C5: pilot trial 3's stream carries `permission_denied` for `tool_name: "Skill"` ("Execute skill: ad-ground") under `acceptEdits`, which is the prompt this rule removes, and the Claude Code adapter maps a `Skill` tool call to `skill_invoked`. Medium: documented and publicly used, not yet exercised through this lane.

### E5 — Live `file_write` paths are relativized against the tracked fixture root instead of the trial copy, and the effects grader rejects them

**Strength:** High
**Provenance:** C6, C7

C6: `runLive` passes `fixtureRoot: resolve(root, caseRecord.fixture)` to `buildLiveReceipt`, which hands the same value to `captureTrial` for every trial, while each host ran with `cwd: trialRoot` under the work root; `trialPath` strips only a prefix equal to the root it is given, so the pilot receipt's three `file_write` events read `/private/var/folders/.../agentic-eval-live-cu0pP8/t1/doc/research/0001-ground-git-hooks-runner.md`. C7: `GRADERS.effects` over one event with that path shape and `allowed_effects: ['doc/research/*.md']` returns `hard_failure: 'unauthorized_effect'`. High: read in code and reproduced with the shipped grader.

### E6 — A hook inherits the host's environment, so the lane can place the gate's evidence per trial and switch the gate off per arm

**Strength:** High
**Provenance:** A3, C8

A3: "A hook process inherits the parent environment, apart from the `OTEL_*` exporter variables", and "Handlers run in the current directory with Claude Code's environment." C8: `artifact-gate.mjs` reads `AD_ARTIFACT_GATE_EVIDENCE_DIR` for the evidence file's directory and `AD_ARTIFACT_GATE=0` as its kill switch, both contract-tested by spawning the script with those variables set; `runLive` spawns the host with the lane's own environment, so a variable set by the lane per trial, or exported by the operator for a whole run, reaches the hook. High: documented inheritance and the gate's tested contract.

### E7 — The corpus accepts a new representative only with three case types, two receipt intents per case, and requests free of skill names and trigger phrases

**Strength:** High
**Provenance:** C9, C10, D2

C9: `coverageReport` lists a gap for a representative without a `positive`, a `close-negative` or `dormancy`, and a `coexistence` case, and for a case without a `known-good` and an `intentionally-broken` receipt; `test/eval-harness.test.js` fails any natural request containing the representative's or the expected route's name or a quoted phrase of their `description:`. C10: `ad-ground`'s quoted phrases are "ground this", "research before coding", "how to approach"; `ad-research`'s are "should we adopt X", "A vs B", "state of the art", "evaluate options", "literature review", "research this"; `ad-ground` is workflow-operational under ADR-0007 and carries no `disable-model-invocation`, so it is model-invocable under ADR-0073. D2: the three existing families landed as case, fixture, and receipt triplets in one commit each, the shape this family follows. High: the rules are executable tests.

## Limitations and reversal

The record establishes documented host behavior, two in-repo measurements (E3, E5), and the pilot's capture; it does not establish that a full trial under `--setting-sources project --allowedTools Skill` routes and converges, which is what the first tracked trial measures. The account's MCP connectors stay in the session under any setting source, so the context is never bare on this machine. The Codex fixture wiring is exercised offline only, because project hooks load only when the `.codex/` layer is trusted and the operator's CLI refuses the account's models. Reversal evidence: a tracked trial in which the fixture's hook does not fire, or in which the `Skill` call is still denied under the allow rule, reverses E1 or E4 and moves the runner to `--permission-mode bypassPermissions` or the gate wiring to an absolute path resolved by the lane; a host release that lets personal skills load under `--setting-sources project` reverses E3 and requires `--bare` with an API key.

## Addendum 2026-09-21: the first tracked trials

Two authorized trials of `research-before-implementing-positive` ran through `eval/run.mjs live` on Claude Code 2.1.227 with the runner this record proposes, one with the gate wired and one with `AD_ARTIFACT_GATE=0` exported in the lane's shell. Three claims move. E4 rises to Measurement for this host version: under `--allowedTools Skill` the `Skill` call for `ad-ground` ran without a prompt in both arms and the stream carries a native `skill_invoked`, so the route grader graded without the Task 0082 inference. E3 is confirmed on a full trial: the init record listed the 46 installed project skills plus the built-ins, no plugin, no user hook, and, unlike the probe, zero MCP servers, so `--setting-sources project` left the session with only what the fixture and the account's built-ins supply. E5 had a second half the record did not see: the host reports its working directory resolved through the macOS temporary-directory symlink (`/private/var/...`) while the lane relativized against the unresolved path (`/var/...`), so the first receipt still carried absolute paths; the lane now relativizes against the resolved trial root, and the receipt was re-derived from the same captured bytes (identical capture digest) with the corrected lane.

One design fact surfaced that no source predicted: with `ad-ground` installed inside the trial copy, the model read the record template from `.claude/skills/ad-ground/references/` in both arms and wrote a record that validated on its first write, so the gate fired once with `validator-passed` and surfaced nothing. The pilot's non-convergence came from an unreadable template, not from the record contract; the gate's feedback value therefore depends on the template being out of reach, which this fixture removes. The numbers and the disposition are recorded in Task 0084 Notes; no gain claim follows from one trial per arm.
