## Context

Fresh-context review of the v0.2.0-beta.1..v0.3.0-beta.1 range (PR #2 merged into `cli`) ran via `agentic-review` on 2026-05-09 against handoff `.agentic/reviews/2026-05-09T19-51-15Z-v0.2-vs-v0.3.md`. Two Blockers and one UX Concern (init.js ACTION_SYMBOL) plus one vacuous test (Concern 7) were addressed in [Task 0009.5](../adr/0009-update-mechanism.md) follow-up commits and shipped as v0.3.0-beta.2. One Blocker (Blocker 2 — "skip should record prevSha not sourceSha") was rejected after tracing the semantics: skip means "user acknowledged this kit version", so recording the current SHA is correct — recording the prior SHA would re-prompt the same conflict on every subsequent run with the kit unchanged. Regression test added in `test/update.test.js` to lock the chosen semantics.

This task tracks the remaining Concerns and Notes from the review that are not patched yet.

## Acceptance Criteria

- [ ] `src/commands/update.js`: `previousAgentsFromStates` and `updateCommand` consolidate `loadState` calls so each agent's state file is read once per invocation. Malformed state errors surface with context.
- [ ] `src/commands/update.js`: `--agent` no longer suppresses interactive mode on a TTY. Only `--yes` and non-TTY suppress the TUI; `--agent` is purely a narrowing flag.
- [ ] `src/lib/install.js`: `removeOrphanSkills` warns when `unlinkSync` would have run against a file that does not exist (state inconsistent with reality). Action type distinguishes "removed" from "missing-on-disk".
- [ ] `src/commands/update.js`: `--dry-run` invokes `updateRootDoc` in a read-only / preview path so the dry-run summary covers AGENTS.md / CLAUDE.md changes.
- [ ] `src/commands/update.js`: managed-skills section in `AGENTS.md` / `CLAUDE.md` follows the same default-skip posture as skill files when the user has edited content between the markers (rather than silently overwriting on `--yes`).
- [ ] `src/lib/state.js` `orderState` guards against missing `files` property on a skill entry (defensive — current callers don't trigger it, but a malformed external state file would crash).

## Plan

- [ ] Read `src/commands/update.js` and consolidate the two `loadState` passes; wrap `previousAgentsFromStates` in a try/catch that re-throws with the path that failed.
- [ ] Drop `--agent` from the `interactive = ...` calculation.
- [ ] Extend `removeOrphanSkills` action type set with `removed-missing` and emit a warning line.
- [ ] Add a `dryRun` branch in `updateRootDoc` (or pre-compute the would-be result) so the planner shows the AGENTS.md change.
- [ ] Mirror the three-way diff for the managed-skills block: detect user edits between markers, prompt before overwriting, skip on default.
- [ ] Add a defensive check in `orderState`.
