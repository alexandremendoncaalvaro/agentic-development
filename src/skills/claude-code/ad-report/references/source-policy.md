# Report source policy

## Baseline limitation

The bundled template is derived from approved official research-report guidance.
No private owner or team report corpus has been authorized. Do not imply that the
baseline represents the owner's historical report pattern or a team standard.

## Access boundary

Text already pasted into the conversation and an artifact already attached for
this report may be read only within that supplied object. Clarify its author and
date when provenance would materially affect the conclusion. Merely naming a
private service, path, repository, connector, channel, or document set does not
authorize a read. Before accessing it, obtain approval for that exact source,
scope, author filter and author class, relevant date range, report purpose, and
retention mode. A supplied public URL authorizes only that URL; do not expand into
adjacent authenticated sources.

If a connector or source is inaccessible, work from supplied text, authorized
local files, public owner-supplied URLs, or the bundled baseline. Preserve the
missing-evidence limitation. The workflow does not fabricate findings, provenance,
prior owner patterns, team conventions, or source access.

## Evidence use and retention

Use the smallest evidence set that supports the question and material findings.
Keep observation, method, inference, and recommendation distinguishable. Recency,
length, reactions, and popularity do not establish evidence quality.

Normal report work is read-only with respect to templates and retains no new source
body. Reusable template improvements route explicitly to `ad-template-tune` and
all of its authorization, retention, one-delta, and write-approval gates.
